# 08 · 视觉规范

本文件是公开包的视觉规格权威源：画布、字体、色板、版式、图示和检查集中于此。它是一套可替换的制作基线，不是所有账号必须遵守的审美标准。角色与账号适配见 `09-换成你自己的账号.md`。

## 1. 配色

### 当前合成示例色板

| 角色 | HEX | 用途 |
|---|---|---|
| PAPER | `#FAF5E7` | 浅纸底色；实际制作取底图实测值 |
| INK | `#24212A` | 墨色、文字与轮廓 |
| ACCENT | `#BB3046` | 关键词、主体强调部位 |
| ACCENT2 | `#2E65A1` | 小面积色块与对照 |

规则：

1. **纸色 CIE L*>92**，不是 HSL、HSV 或未线性化亮度。保持文字可读与浅纸观感。
2. 通常两至四个主色；物种本色、眼白、肤色等必要点缀另外登记，不能为限色改错形态。
3. 高饱和色只做小面积强调，不做纸底。两个强强调色之间用墨色或纸色分开。
4. 关键词强调色与主体对应部位一致，让文字与画面连成一件事。
5. 新纸色对全部已登记纸色 ΔE76≥8；无合格新色可显式复用明亮旧色，另换强调色与构图并登记。保持 L*，不为求新降亮度。
6. 同一集四卡使用同一色板、同一张底图；换纸色时重新生成质感，不为单卡单独换底图。

```python
def Lstar(hex6):
    def lin(c):
        c /= 255
        return c / 12.92 if c <= 0.04045 else ((c + 0.055) / 1.055) ** 2.4
    r, g, b = (lin(int(hex6[i:i + 2], 16)) for i in (1, 3, 5))
    y = 0.2126 * r + 0.7152 * g + 0.0722 * b
    f = y ** (1 / 3) if y > 0.008856 else 7.787 * y + 16 / 116
    return 116 * f - 16
```

## 2. 字体

| 用途 | 字体 | 字重 |
|---|---|---|
| 标题、正文 | Noto Sans CJK SC | 900 或按层级降低 |
| 数字、衬线强调 | Noto Serif SC | 900 |

安装族名必须与 CSS 一致：`Noto Sans SC` 不等于 `Noto Sans CJK SC`。字体来源见 <https://github.com/notofonts/noto-cjk/releases>，许可证与具体下载资产以该项目为准。

不使用 `@import` 或远程 webfont。中文各字体的字宽可能一样，不能靠文本宽度判断静默降级；用 `scripts/_fontcheck.mjs` 的截图/墨迹检查。缺字体报错，不把空的 `fc-list` 输出直接当“没安装”。

## 3. 画布与倾斜

```text
画布：1080×1440 CSS px，3:4
输出：2160×2880 物理像素，deviceScaleFactor=2
底图：2160×2880，精确比例 0.75
左右主要内容边距：至少 54px
```

旋转造成的额外垂直占用近似为 `行宽×|sinθ|`，还要加本身行高。短行二至四字可试 ±14°至20°，五字以上长行优先 ±3°至7°；这些是起点，不替代实测外框。

逐行错角、相邻行方向相反；需紧凑时考虑水平错位，不把所有行都大角度纵向堆叠。

## 4. 首图规格（代码主体）

四段式见 `03-四张图.md`：场景锚点、动作、设问、反常结果。示例字号短行 98px、长行 136px、色块 104px；色块只给最要紧的关键词，硬错版影约 8px。按实际字宽与角度重新量，不能只看字数。

代码主角可从 320–400px 宽起步，强调色落在主体上。这不是生图主体的大小上限。顶部刊头和底部数据条不属于本套默认基线；有独立内容职责时另定。

## 4b. 生图封面大框（按题可选）

需要让表情、关系或氛围承担主题时，可用两行大字加大框；不是每集强套。吉祥物会冲淡情绪时不放，模板 `COVER_EYES=None`。

```text
大字 r1：left 56 / top 98 / 80px / -3° / letter-spacing -.05em
大字 r2：left 56 / top 232 / 104px / +3°
话题色块：ACCENT底 / 白字 / padding 2px 24px 15px / INK硬阴影9px
框外沿：x91 / y457 / w898 / h650
边框：10px / 圆角26px / 下右硬阴影14px
半身主体：trim=True / focus≈0.40；底边在框外裁掉
吉祥物（可选）：0.42倍，脚底中心(168,1258)/(914,1258)，外倾±6°
底线：left/right56 / bottom70 / 上边线5px / 字40px / line-height1.35
```

字数只是粗上限，按真实内容和网点位置验。圆形月洞门或竖向构图可另定框形，当前模板只内置上述矩形；非人物大框未全量验证，不把它当全题材最优布局。

## 5. 答案图规格

结构：`hd / lead / 图 / t1 / 可选note / src / 可选final`，详见 03。导语把结论直接说清，图后配一两句人话，硬数字写进句子，不强塞三条要点和数据块。

- 主要正文≥27px，功能来源行可更小，最低字号16px。
- 标题≤8字只是长度上限；色块右端还要避开当张网点最左 CSS x。
- 几何门禁不自动判标题是否“语义上压网点”，须看缩略图；相交时缩短、换行或重排。
- 来源行保留作者、年份，详细出处放发布文案。
- 限定框整集尽量不超过一个；健康安全提醒按其实际用途区分，不把普通底栏命名为 note。

## 5b. 四卡、机制与彩蛋

固定支持 `1_cover / 2_answer / 3_mechanism / 4_egg` 四张。第五张需要先扩模板、命名和自动检查，不临时绕闸。彩蛋放最后，不在正文提前复述。

机制主体可复用生图，但结构、因果箭头、数量、刻度和标注用代码。相同侧面剪影纵向叠压会遮掉头部，优先并排示意、用文字交代写实动作。

同色剪影接触时加纸色外描边，blur=0：

```css
filter: drop-shadow(7px 0 0 PAPER) drop-shadow(-7px 0 0 PAPER)
        drop-shadow(0 7px 0 PAPER) drop-shadow(0 -7px 0 PAPER);
```

从同一个 SVG 派生角色，必须改实际几何，不能只改注释。数据条刻度必须真正等分；不能用布局居中暗示错误占比。

## 6. 代码角色参考

代码生物可采用扁平几何图鉴风；翅膀用 PAPER 填充与 INK 描边，强调部位跟色板走。解剖顺序和结构来自核查，不能因“好看”把腿画在腹部。眼型复用 `templates/mascots.py`；需要嘴、亲吻或跨生物互动时见 12。

## 7. 底图

Flash 默认，只生成纯纸纹、网点、褪色渍和折痕，无文字与主体。模型先出近白质感，`--paper` 事后映射颜色。

- Flash 原生1856×2480，按脚本用 Lanczos 放到2160×2880；不可任意用低分辨率底图拉伸。
- 最终必须真 PNG、比例0.75、尺寸2160×2880、L*>92。扩散模型返回错尺寸或假 PNG 时不悄悄修成成功。
- 网点主要在右上；每张底图位置有波动，读取实际网点左缘，不沿用旧固定坐标。
- 同一集四张共用一张底图；网点撞文字先重排，不为一张卡另生底图。

后缀不能证明格式，build 的 `check_bg()` 再查魔数、比例和尺寸。JPEG 转成 PNG 不会恢复已损失的细节。服务商像素区间、模型状态和参数以当前文档为准，调用细则见07。

## 7b. 生图主体层

人物、动物按情绪与准确性分工，详见12；框内场景和文字仍用代码。

| 项 | 规格 |
|---|---|
| 框 | 圆角26、边框10、硬阴影14；框内浅底用 `paper_light(PAPER, white=0.65)`，不是纸白各半 |
| 深色场景 | `art_frame(scene=...)` 在主体下方；深色主体加 `outline=PAPER`；先在深底查抠图碎边 |
| 半身裁切 | focus约0.40–0.42，底边出框；focus不用于其他主体 |
| 其他构图 | `fit=waist/full/object/closeup`，不要硬套人脸焦点 |
| 色 | 色名提示、后处理吸附当集色板；必须包含物种本色、眼白及必要深墨色 |
| 纸纹 | 同一张底图按画布坐标对齐、multiply、opacity0.45；主体小图用自身alpha作遮罩 |
| 标注 | `overlay` 在纹理上方、不参与multiply；目标点从原图像素换算 |
| 吉祥物 | 代码常规眼型优先；要嘴或互动用参考图，逐张验造型；按题可不放 |
| 文字 | 全部代码，无模型文字、伪字、水印；封面小字与画面意思一致 |

## 8. 制作禁忌与需复核项

高饱和满底、长行大角度、中文字行距过低、同色主体糊团、照片盖字和字体静默降级都要处理。纯代码与生图同卡时分别检查，而不是看“像同一个画风”就算通过。

生图情绪可大胆表达；恶心、害怕与不适分数只是提醒，不自动否决。保留事实、形态和基本安全原则，成稿交负责人看图调整。平台与 AI 标识见14，不能承诺必过。

## 9. 交付前门禁

```bash
node scripts/social-card-qa.mjs 第N集-XX/素材/1_cover.html
```

| 规则 | 检查 |
|---|---|
| R1 | 画布溢出 |
| R2 | 底部固定元素碰撞 |
| R3 | 元素越界 |
| R4 | 行墨迹碾压、不透明块或位图盖字 |
| R5 | 最小字号 |
| R6 | 字体静默降级 |
| R7 | 未替换变量或占位符 |
| R8 | 内容覆盖率，WARN须结合真实内容处理 |
| R9 | 图片、SVG image、CSS背景资源缺失 |
| R10 | 文字对比度，严重位图压字可FAIL，其余按脚本报告 |

FAIL须修；WARN逐条处理，不能把占位模板的低覆盖率当最终验收。截图脚本在常规定稿路径强制去 AI 味，QA仍须另跑；非标准目录或预览开关不等于已验收。

门禁测不到全部位图含义、物种形态、衣襟、图注真假、网点与标题的视觉冲突、同色糊团和刻度语义，仍须整张看图与独立审稿。修改门禁要双向回归：故意坏样本被拒，已认可的好样本仍通过。
