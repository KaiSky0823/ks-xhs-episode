## 1. 配色

| 角色 | HEX | 用在哪 |
|---|---|---|

### 换色时必须守的规则

1. **底色 CIE L\* > 92**。Kai 明确否掉过牛皮纸、暗黄、墨绿、靛蓝，理由都是「不够亮 / 太暗淡」。

   ⚠️ **必须用 CIE L\***，不是 HSL 亮度、不是 HSV 明度、不是未线性化的加权和。
   这条以前只写「明度 > 92%」没写算法，三种算法能差 5~25 个点，扩色板时必然选错纸
   （实测：孔雀青 `#00A0A8` 按 HSV 算 65.9「看着还行」，按 L\* 算只有 59.9，它是个中深色）。

   ```python
   def Lstar(hex6):                      # '#FCEADF' → 93.8
       def lin(c):
           c /= 255
           return c/12.92 if c <= 0.04045 else ((c+0.055)/1.055)**2.4
       r, g, b = (lin(int(hex6[i:i+2], 16)) for i in (1, 3, 5))
       Y = 0.2126*r + 0.7152*g + 0.0722*b
       f = Y**(1/3) if Y > 0.008856 else 7.787*Y + 16/116
       return 116*f - 16
   ```

   选 L\* 的依据（2026-09-01 实算）：四套已认可的纸色 L\* 是 92.9~95.6，**阈值 92 原样成立**；
   Kai 否掉的四个是 25.3~70.4，**全部远低于 92**。认可的最低 92.9、否掉的最高 70.4，
   中间空了 22 个点 —— 阈值放哪儿都不敏感，说明这条规则抓的是真东西，不是拍出来的数。
   换成另外两个算法都要重新标定阈值，且简化加权会把浅灰蓝（91.9）误杀。
2. **2–4 个颜色**，不能只有 2 个（不够撞），也别超过 4 个（会乱）。
3. **高饱和色只做 accent，永远不做 paper**。这是「撞色而不俗」的关键——
   荧光黄满底 + 大字之所以俗，问题不在选了黄色，而在**把强调色当底色用**。
4. **禁荧光色系**。`#B6E32E` `#FF6A18` 这类抓眼效率最高，但气质偏潮牌／运动风，
   离「俗」更近。用 20 世纪印刷专色（朱红、钴蓝、橄榄绿、洋红、孔雀青、桃红）。
5. **钴蓝 `#1B4D8F` 不做底色**，做小面积色块可以。
6. **两个高饱和色永不相邻**，中间必须隔着墨色或底色。
7. **强调色 = 插画主体的颜色**。文字里的关键名词和苍蝇复眼用同一个色，
   文字和图才是一件东西，不是各画各的。

## 2. 字体

| 用途 | 字体 | 字重 |
|---|---|---|
| 标题 / 正文 | Noto Sans CJK SC | 900 |
| 数字 / 衬线强调 | Noto Serif SC | 900 |

两款都是 SIL OFL，可商用。下载地址（实测可用）：

```
Noto Serif SC     https://github.com/notofonts/noto-cjk/releases/download/Serif2.003/14_NotoSerifSC.zip
                  解压后 SubsetOTF/SC/NotoSerifSC-*.otf 全部丢进 ~/Library/Fonts/
Noto Sans CJK SC  https://github.com/notofonts/noto-cjk/releases  → Sans2.004 → 08_NotoSansCJKsc.zip
```

⚠️ **Sans 千万别拿错资产**：`14_NotoSansSC.zip` 是**另一个族**（Noto Sans SC，
新的按语言切分版），**族名和 CSS 里写的 `Noto Sans CJK SC` 对不上，装了也不会被匹配到**。
要的是 `08_NotoSansCJKsc.zip`。

⚠️ **别用 `fc-list` 自检** —— macOS 不一定装了 fontconfig，`command not found` 一旦被
`2>/dev/null` 吞掉就返回空，看起来像「字体没装」，比真没装更难查。用：

```bash
ls ~/Library/Fonts | grep -iE "NotoSerifSC-Black|NotoSansCJKsc-Black"
```

⚠️ **判断字体有没有静默降级，不能用文本宽度** —— 汉字在几乎所有中文字体里 advance
都精确等于 1em（实测四种字体全是 114px），宽度永远相同。
必须用**截图哈希**或**墨迹高度**（canvas `TextMetrics` 的 actualBoundingBox）。

⚠️ **不要用 `@import` 拉 Google Fonts**。中国大陆网络下大概率降级，
且 `networkidle` 会一直等到超时。用本机已装字体。

## 3. 画布与倾斜

```
画布      1080 × 1440 CSS px（3:4）
出图      2160 × 2880 物理像素（deviceScaleFactor: 2）
底图      2160 × 2880 ← 必须按物理像素出，不是按 CSS 尺寸。见 §7
左右边距  ≥ 54px
```

小红书会对上传图二次压缩，源图分辨率高一档，压完更清晰。

### 角度分配（**这条是几何硬约束，不是审美偏好**）

```
一行旋转 θ 后，它吃掉的垂直空间 = 行高 + 行宽 × sinθ
```

实测：
- 3 字 × 98px = 294px 宽，转 17° → 只多吃 **86px**
- 5 字 × 136px = 680px 宽，转 17° → 要多吃 **199px**
- 7 字 × 130px = 910px 宽，转 15° → 要多吃 **236px**

**所以：**

| 行长 | 角度范围 |
|---|---|
| 2–4 字（短行） | **±14° ~ ±20°** ← 冲击力靠这些行 |
| 5 字以上（长行） | **±3° ~ ±7°** |

四行全给大角度，1440px 高度**装不下**。而且长行斜太多本来就难读。

### 排版取向

- **逐行错角** > 整块统一倾斜（Kai 选中的 H / L / M / P 全是逐行错角）
- 相邻两行角度**方向相反**，形成咬合而不是平行
- 想同时要「大角度」和「紧凑」，唯一的解是**水平错开**，不是垂直拉开

### ★答案图标题必须 ≤ 8 字（门禁拦不住这条）★

答案图的标题色块是**从左横过去的全宽带**，底图网点钉在右上（实测占 CSS x ≥ 714）。
标题越长，色块右端越往网点里伸。mac mini 侧实测：

| 标题长度 | 色块右端 | 距画布右边 | 门禁 |
|---|---|---|---|
| **8 字（当前）** | 913 | 167px | ✅ 0 FAIL |
| 9 字 | 1013 | 67px | **✅ 放行了 ← 缺口** |
| 10 字 | 1112 | 超出 32px | ❌ R1 拦下 |

**9 字那档是门禁的缺口**：几何上没越界所以放行，但色块右端和桃红错版影正好压在密集网点上。
色块和网点同为橄榄绿，一接触，**色块的右边界就糊掉了** —— 看起来像从网点里「长出来」，
而不是干净地压在纸面上。

门禁拦得住「跑出画布」，拦不住「压在网点上」——正是 §9 那三件必须人眼看的事的第 1 条。

→ **在把它做成第 9 条门禁之前（样本不够，见 §9 末），用这条人工规则：答案图标题 ≤ 8 字。**

## 5b. 一集几张图 · 机制图示 · 彩蛋图

第 2 集之后定的结构（Angel 反馈「图太少」「有些文字表达的是不是也可以用图片再展示下」）：

| # | 类型 | 干什么 | 必须吗 |
|---|---|---|---|
| 1 | 首图 | 钩子，四段式 | 必须 |
| 2 | 答案图 | 三条要点 + 一个硬数据 | 必须 |
| 3 | **机制图示** | 把「空间/动作关系」画出来，不写成字 | 有机制就做 |
| 4 | **彩蛋图** | 一条能独立成立的反常识，压在最后 | 有就做 |

彩蛋**要做成图**，不要只写在正文里。理由是实测出来的：第 2 集正文原本第二句就是彩蛋
（市售蛋未受精），做成第 4 张图之后，正文那句必须删 —— 留着既重复又提前剧透。
正文改成把人往最后一张带（「最后一张更离谱，跟我早饭有关」）。

### 机制图示的两条硬规矩

**① 不用 Seedream 画图示。** 生图模型标不准中文标注、控不了标注位置、每次生成还是
不同的角色。图示走 SVG，和分层原则一致：Seedream 只出底图质感那一层。

**② 同姿势的侧面剪影不能纵向叠。** 第 2 集要画「公鸡踩到母鸡背上」，试了三版都失败：
这套 SVG 是侧面站姿 + 大尾羽 + 大肚子，两只纵向叠放时，下面那只的头天然落在上面那只
身体的正下方 —— 母鸡被整个吃掉，只剩一坨黑圆，看起来像一只鸡长了两个头。
加纸色描边也只救回头颈。

→ **改成并排示意**（一只水平翻转，两者身体后端相对），接触点标在正中。
两只都完整、都有头、标记看得见。写实的那一步（踩背）用副标题一行字补上。
图示的目的是把「怎么发生」说清楚，不是还原姿势。

### 同色剪影必须描边分离

两个同为 INK 剪影的角色只要挨着，就会糊成一块。给下层那个描一圈纸色外轮廓：

```css
filter: drop-shadow(7px 0 0 PAPER) drop-shadow(-7px 0 0 PAPER)
        drop-shadow(0 7px 0 PAPER) drop-shadow(0 -7px 0 PAPER);
```

blur 必须为 0，否则是阴影不是描边。

### 从同一个 SVG 派生第二个角色

别为「母鸡」另画一个 SVG —— 同一血统派生，两只鸡才一眼是同一套画法。
但**派生必须改几何，不能改注释**。第一版写了
`s.replace('<!-- 肉垂', '<!-- 肉垂（母鸡更小）')` —— 只改注释不改 path，
出图肉垂和公鸡一样大，是个假修改。

改之前先读原 SVG 的坐标。第 2 集这只：头 = `circle(300,126,r56)`，头顶 y=70；
y=82 处头的半宽 = √(56²−44²) ≈ 34.6，所以低冠的底边只能落在 x∈[265,335]。
第一版把低冠放在 (243,150) —— 那是脖子，出图就是「脖子上长了两颗红瘤」。

母鸡 = 低冠贴头顶（三小瓣，不拔高）+ 肉垂缩到原长一半以下。其余全部复用。

### 数据条的刻度不能撒谎

图示里画「有多快」这类条，刻度必须真的等分。第 2 集第一版用 `space-between` 把
「眨一次眼 ≈ 0.3 秒」顶在条的正中央 —— 等于暗示 0.3 秒 = 半程，而它应该在 3% 处。
门禁测不到这种错（它只管几何不管语义）。要么放真刻度（0/5/10 秒），要么别放。

## 7. 底图

Seedream 5.0 lite 只出**纯质感**：纸纹、半色调网点飞溅、褪色渍、折痕。
**不含任何主体，不含任何文字。**

```
尺寸    2160 × 2880   ← 物理像素，不是 CSS 尺寸
比例    必须精确 0.75（= 2160/2880 = 1080/1440）
格式    PNG
模型    doubao-seedream-5-0-lite-260128 + --no-fallback
网点    只在右上角；左侧 / 中部 / 下部必须完全干净
```

`scripts/gen_bg.py` 已把这些写死并自验，正常情况下不用手动传参。

### 为什么是 2160×2880 而不是 1080×1440

CSS 是 `background: url() center/cover`，**底图要全幅铺满画布**。
画布 1080×1440 CSS px 在 `deviceScaleFactor: 2` 下 = 2160×2880 物理像素，
所以底图必须按**物理**像素出，否则会被放大。

**实测放大的代价**（拉普拉斯方差，越高越锐利）：

| | 方差 | 相对 |
|---|---|---|
| 原生 2160×2880 | 64.3 | 100% |
| 1680×2240 放大到 2160×2880（1.286×） | 24.3 | **38%** |
| 左上网点最密区 | — | **37%** |

**1.286× 的双线性放大吃掉约 62% 的高频细节。** 纸纹和网点全是高频内容，
放大后「从印刷变成打印机脏了」—— 而且**只在全尺寸暴露，缩略图上看不出来**。

### 为什么比例必须精确 0.75

`cover` 的语义是「铺满并裁掉多余部分」。比例和画布一致时不裁不偏、1:1 精确铺满。
一旦不一致（比如手滑写成 2048×2048），**cover 会居中裁掉两侧 ——
钉在右上角的网点会被直接裁出画面，而且不报任何错**，底图只是看起来「变干净了」。

→ `gen_bg.py` 里有一条硬断言：比例 ≠ 0.75 直接失败。

### 为什么网点钉右上

文案区固定在**左侧和下部**。底图的网点位置是扩散模型的随机结果，
**每换一次文案都可能撞上**（实测发生过：新底图的网点正好压住标题第一行）。

⚠️ **「文案区在左侧和下部」这个前提只对首图成立**（首图与网点实测零重叠）。
**答案图的标题是全宽横带**，右端会伸进网点区 —— 所以答案图另有一条 ≤8 字的长度约束，见 §5。

→ 把它从**随机性问题**变成**规格约束**：prompt 里明令「只在右上角有网点飞溅，
左侧/中部/下部保持完全干净」。这是可复现的前提。

### 为什么必须 PNG 且禁止降级

纸纹网点是 JPEG 最不擅长的高频内容，压缩会出块状伪影，垫在文字层下面会脏。

要 PNG 就必须让请求带 `output_format=png`，而**只有 5.0-lite 认这个字段，4.5 不认**。
降级到 4.5 时脚本会**自动把这个字段摘掉** → 请求成功(200) → 服务端默认返回 JPEG
→ 字节写进你给的 `.png` → **拿到「名字叫 .png 的 JPEG」，而 exit code 仍是 0**。

→ 所以 `--model 5.0-lite --no-fallback` 不是为了避免报错，是**堵死静默降级成 JPEG 这条路**。
→ 并且 `gen_bg.py` 落盘后**自己再验一次 PNG 魔数**，不只信 exit code。

#### ⚠️ 这道防线被绕过去过（2026-08-29 查出）

第 1、2 集的底图**两张都是 JPEG**，文件名却是 `.png`。魔数 `ffd8ffe0`，不是 `89504e47`。

成因：`gen_bg.py` 的魔数自验是 08-24 加的。`tex_blush` 生于 08-22（早于自验，能解释），
但 `tex_cream` 生于 **08-28，晚于自验** —— 说明生成时根本没走 `gen_bg.py`。
（具体当时用了什么方式没有日志，这一句是推断。）

**教训：脚本里的闸只能挡住走这个脚本的人。** 光靠「记得用 gen_bg.py」这条纪律拦不住。
所以 `build_template.py` 开头加了 `check_bg()` —— 每次出图都验底图的魔数、比例、尺寸。
绕过 `gen_bg.py` 也逃不掉，因为出图这一步绕不过去。

**处置**：两张底图已用 PIL 重存为真 PNG，**像素级无损**（sha256 相同）。
但重出的图和原图有最大 38/255 的差异 —— PIL 和 Chrome 的 JPEG 解码器实现不同
（IDCT / 色度上采样），所以「同样的 JPEG」在两边解出来本来就不是同一组像素。
差异全在纸纹层，文字和 SVG 是矢量渲染不受影响，四张图已重出并复核观感无变化。

### 其它已实测的参数行为

| 参数 | 实测 |
|---|---|
| `watermark=False` | ✅ 生效，出图无「AI生成」角标 |
| `background="transparent"` | ⚠️ **被 API 接受但不生效**，返回的仍是 RGB 无 alpha。分层不需要 alpha，不传 |
| ARK 像素合法区间 | `3,686,400 ≤ 宽×高 ≤ 16,777,216`（= 4096²）。2160×2880 = 6,220,800，余量 2.7 倍 |
| `--n` 多张 | 拿不到承诺张数（`sequential_image_generation=auto` 的语义是让模型自己决定）。要确定张数就多次单张调用 |

⚠️ 即使 prompt 明令零文字，**仍要人眼过一遍** —— 模型偶尔会画出像文字的笔画。

### 底图复用（重要）

**同一集的四张图（钩子 / 答案 / 机制图示 / 彩蛋）必须共用同一张底图。**
各生一张的话，纸纹走向、网点飞溅的位置、污渍分布全都不同，放在一起就不像一套了
—— series 感恰恰来自这些「不重要」的细节完全一致。

换色板（集与集之间轮换，见 §1）时才生新的；同一集内现有底图的网点正好压住新文案，
优先挪文案，不要为一张图单独生底图。

## 8. 禁忌清单

| 禁 | 原因 |
|---|---|
| 高饱和色做底色 | 「俗」的真实来源是色彩面积失控，不是选了哪个颜色 |
| 荧光色（`#B6E32E` `#FF6A18` 之类） | 抓眼但气质偏潮牌 |
| 钴蓝做底色 | Kai 明确不喜欢 |
| 黄色调整体 | Kai 明确否掉 |
| 底色明度 < 92% | 一律被判「暗淡、不够吸睛」 |
| 中文 `line-height` < 1.05 | 相邻行墨迹必碾压 |
| 长行给大角度 | 垂直空间不够，必然撞行 |
| 让扩散模型画中文字 | 实测会多字、错字、出界 |
| `@import` Google Fonts | 国内网络降级 + networkidle 超时 |
| 首图加顶部刊头 / 底部数据条 | Kai 明确要求去掉 |
| 直角引号 `"..."` | 中文排版用「」 |
| 依赖 `~/Library/Caches/ms-playwright` | 该目录可能被清理工具周期性清掉（MacBook 侧实测发生过两次），用系统 Chrome |
| 底图按 CSS 尺寸出 | 要按物理像素 2160×2880 出，否则高频细节只剩 38% |
| 底图比例 ≠ 0.75 | `cover` 会居中裁切，钉在右上的网点被裁掉且不报错 |
| 底图用 JPEG / 允许降级到 4.5 | 会静默拿到「名字叫 .png 的 JPEG」，exit code 仍是 0 |
| 用文本宽度判断字体降级 | 对中文无效，汉字 advance 恒等于 1em。用截图哈希或墨迹高度 |
| 用 `fc-list` 查字体 | 机器可能没装 fontconfig，报错被 `2>/dev/null` 吞掉后看起来像"字体没装" |

## 9. 交付前必过的门禁

```bash
node scripts/social-card-qa.mjs out/cover.html
```

`exit 1` 就是不合格，**必须改到过，不要肉眼放行**。八条规则：

| 规则 | 查什么 |
|---|---|
| R1 | 内容溢出画布 > 4px |
| R2 | 与底部固定元素碰撞 > 6px |
| R3 | 元素越出画布边界 > 4px |
| R4 | 行间墨迹碾压 / 不透明块遮挡 / 两个文字元素交叠 |
| R5 | 最小字号 < 16px |
| R6 | 首选字体静默降级 |
| R7 | 模板变量未替换 |
| R8 | 内容覆盖率 < 35%（WARN，克制型构图可豁免） |

### 门禁**测不到**的六件事，必须人眼看

1. **底图内容与文字打架** —— 脚本只测 DOM，底图里画了什么它一无所知
2. **文字溢出色块**（没超画布所以不报）
3. **底图里混进了文字笔画**
4. **SVG 图形盖住文字** —— R4 只认不透明的 DOM 块，SVG 内部的 path 不算
   （第 2 集实测：公鸡的肉垂把「泄殖腔」三个字盖掉了，门禁 exit=0）
5. **同色剪影糊成一块** —— 两个 INK 剪影挨着，几何上各自安好，视觉上是一坨
6. **图表在语义上撒谎** —— 刻度位置暗示了错误的数值，门禁只管几何不管意思

### 门禁自己也会错 —— 改完必须双向回归

已修的四个 fail-open + 一个 fail-closed（后者是第 2 集发现的）：
R4 的 `linesOf()` 会把块级子元素（如 `<small>`）的**外框** rect 当成一行，
和它自己的第一行比出根本不存在的 18px 碾压。修法是剔掉纵向完整包含另一个 rect 的外框。

**每次动门禁，两边都要验**：
- 阴性：故意注入 bug 的样本必须 `exit=1`（大角度行碾压 / 越界 / 不透明块盖字）
- 阳性：所有已认可的成品图必须仍 `exit=0`

只验一边等于没验 —— 只验阳性会放过假闸，只验阴性会留下误报把好设计拦在外面。

### 关于把「压在网点上」做成第 9 条门禁 —— 等第 3-4 篇

技术方案是清楚的（`gen_bg.py` 出图时顺手算一张粗网格「忙碌度」mask.json，
`social-card-qa.mjs` 加 R9 读它、与 textEls/opaqueBlocks 求交；忙碌度用拉普拉斯能量，
色相无关，换色板也成立），工程量约半天。

**卡住的不是代码，是标定样本。** 现在只有 1 张底图 + 2 个版式，能做的只是两点标定
（8 字必须过、9 字必须报）。而门禁**必须做阴性对照**才能证明它有牙——
两个样本定出来的阈值大概率不是误报刷屏就是形同虚设，
那就又交付了一个「永远返回 0 FAIL 的假闸」。

→ **等第 3-4 篇、手上有 2-3 张不同色系底图之后再做，一次做对。**
在那之前用 §5 的人工规则（答案图标题 ≤8 字），成本几乎为零。
