# 02 · 核查协议

每集先核查再定稿。自动化检索或模型输出只能提供线索，不能替代证据判断。

## 核查分工

按选题复杂度安排 2–4 个互不重叠的核查任务；简单题可合并任务，复杂题按信息类型增加专项检查。

| 路 | 任务 | 必须要求 |
|---|---|---|
| A | 原始文献与机制 | 找到原始研究的作者、年份、期刊或机构；记录原文表述、样本与效应量 |
| B | 重复实验与争议 | 核查是否有未能重复、后续修正或相反证据 |
| C | 中文流传版本 | 对比常见说法与原始证据；辟谣题记录传言来源 |
| D | 彩蛋与延伸 | 找相关应用、历史背景或可独立成立的补充事实 |
| E | 画面准确性（适用时） | 对出镜生物、服饰、物件、方向动作列形态 / 空间锚；逐项附可靠图源或文献 |

每个核查任务都要返回：结论、原句或数字、URL、证据强度和未核实项。若所用平台支持独立任务或多 agent，可并行执行；不同运行环境按各自工具选择配置执行者，不能假定存在特定 CLI 命令或模型别名。

### 派单模板

```text
任务：为科普图文选题「<现象>」做发布级事实核查。
只使用环境允许的公开检索和网页读取工具；不要访问登录态浏览器、私人文件或无关目录。
每条给：结论 / 原句或数字 / URL / 强度（一手全文 / 一手摘要 / 二手 / 未证实）。
优先开放全文（PMC、作者主页、J-Stage 旧刊、大学仓储）。

要核的：
1. <具体论文题名 / 作者 / 年份>
2. ...

最后给：「可以印在图上的 3～5 条硬事实」「不能写的过强说法」。
如有画面专项，再加「必须画对的特征」与「空间 / 因果」两张表。
只写下面指定的输出文件：<路径>。
```

## 证据强度

| 档 | 定义 | 能否上图 |
|---|---|---|
| **一手全文** | 审核者读到论文全文、原始数据或官方原始资料中的具体证据 | ✅ 可用，精确数字仍要对口径 |
| **一手摘要** | 读到论文或机构官方摘要的原句 | ✅ 可用，不得超出摘要范围 |
| **二手** | 综述、百科或权威科普转述 | ⚠️ 可作背景，标清来源性质；不要包装成原始研究结论 |
| **未证实** | 只在媒体、自媒体或搜索摘要中出现，未能追到可核来源 | ❌ 不作为硬事实上图 |

## 内容负责人必须做的三件事

自动化检索和 agent 是线索提供者，不是结论所有者；内容负责人负责最终核对。

### 1. 亲自读载重结论的原始来源

图上最核心的数字、关键机制、否定结论应直接读到原文。开放全文常见渠道包括 J-Stage、大学机构仓储、PMC、作者实验室主页和 Europe PMC。

```bash
pdftotext -layout paper.pdf paper.txt
python3 -c "import re;t=re.sub(r'\\s+',' ',open('paper.txt').read());print(t[t.find('Results'):][:2000])"
```

### 2. 处理证据冲突

多路来源不一致时，以可读到的原始证据为先；记录冲突内容、裁定依据和仍未解决的部分。不能因为多数摘要同说法就覆盖相反的原文。

### 3. 对否定断言提高证据门槛

「没人测过」「查无出处」「没有研究」不能由搜索失败推出。精确到小数点的网传数字先追溯源头；找不到时写「本次未能追到出处」，说明检索范围，不声称不存在。

## 核查结论怎么写

落盘到 `第N集-XX/报告/核查结论.md`，模板见 `templates/核查结论.md`。必须有：

1. **可以印在图上**：表述 / 依据（含原句）/ 强度。
2. **不能写**：逐条写出为什么越过证据。
3. **来源**：可点击的 URL 列表。
4. **画面准确性**（有生物、服饰、器物时）：对象 / 必须画对 / 常见画错 / 出处和强度 / 出图后如何核。提示词准确性锚照抄这一栏。
5. **空间与因果**（有方向动作时）：动作从哪一端、哪一侧发生，结论中的左右参照谁。
6. **画面断言清单**：画面细节会让读者以为什么，核查结论是否支持。

另外记录执行者之间的分歧、采用哪条证据，以及没完成的事项（付费墙、来源不可访问、时间限制等）。

## 健康与安全题材

涉及身体、疾病或食品安全时，必须写清证据边界和适用人群；不能只说「没事」。若症状可能涉及急症或需要专业判断，提示读者咨询合格专业人士，不由插画或模型诊断。
