按类型归档。每条都是真事。

## 3. 否定断言翻车（第 4 集，两条全翻）

## 4. 门禁自己会错

| 次 | 症状 | 根因 |
|---|---|---|
| 1 | R4 报 18px 假重叠 | `linesOf()` 把 `<small>` 外框当成一行 |
| 2 | 行内色块盖住自己那行被报 FAIL | 旧豁免「重叠÷色块面积>0.7」因 padding 撑大分母**从未生效过** |
| 3 | 我造的阴性对照根本没注入 bug | 它一直 FAIL 是因为触发了上面那个误报 |

顺带纠正一条错认知：`inline-block` 的 padding **参与**行高，不会压上一行；真会溢出行盒的是 `display:inline`。

**教训**：改门禁必须双向回归（真 bug 要抓到、正常样本要放行），阴性对照要验证它真的注入了 bug。

## 5. 底图规格

第 1、2 集的底图**都是名字叫 `.png` 的 JPEG**。
根因不是「忘了走 gen_bg.py」，是 `gen_bg.py` 硬编码了 mac mini 的路径，**MacBook 上根本跑不了**，于是绕开用了别的脚本，那个脚本不传 `output_format`，服务端默认返回 JPEG。

**教训**：① 第一次归因往往是错的，要查到行；② 闸要设在绕不过去的那一步（`check_bg()` 放在出图脚本开头）。

## 6. 视觉上反复出现的问题

- 绝对定位块叠压（门禁测不到）
- SVG 被 viewBox 裁掉
- 标注指错位置
- 抽象主题找不到主体 → 解法：符号当主体、字本身当主体、物件当「刀」
- 中间大片空白 → 补一条有内容的（不是装饰）

## 7. Kai 的反馈里反复出现的

| 他说 | 意思 |
|---|---|
| 「有点云里雾里，不够直白清晰易懂」 | 主线漂了 / 首图太隐晦 |
| 「有趣度还差不少」 | 笑点全在文字里，图形没承担 |
| 「全面深度地毯式」 | 上多 agent + 读全文，别停在摘要 |
| 「第一轮就要极致」 | 不许等他问「做到极致了吗」才补 |
| 「我实际看到的比这个大很多」 | 参照系没说清（相对身体 vs 相对地面） |

最后一条特别值得记：**读者的直观经验和论文数字冲突时，多半是参照系问题**，要在图上说清，不是改数字。
