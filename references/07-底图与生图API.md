# 07 · 底图与生图 API ★整条流程里唯一的 API 调用★

一集只生成**一张**底图，四张图共用。除此之外全部本地：文字是 HTML/CSS + Chrome 截图，
角色和图示是手写 SVG，门禁是本地 Playwright。**没有第二处 API 调用。**

---

## 为什么不让模型直接出成品图

试过，不行。实测失败模式：
- 中文多字、错字、糊字，一张图里能错三四处
- 文字被裁边
- 同一个角色每次生成都不一样
- 标注位置控不准

所以是**三层分工**：

| 层 | 谁做 | 为什么 |
|---|---|---|
| 底图（纸纹、网点、褪色渍） | Seedream 生成 | 质感是模型的强项，且不含任何需要精确的东西 |
| 文字 | HTML/CSS + Chrome 截图 | 中文永不出错，像素级可控 |
| 角色 / 机制图示 | 手写 SVG | 颜色跟色板走，位置精确，跨集一致 |

**底图里绝对不能有文字、主体、生物。** prompt 里写死了这条约束。

## API 参数（写死，别改）

```
端点    https://ark.cn-beijing.volces.com/api/v3/images/generations
模型    doubao-seedream-5-0-lite-260128
密钥    环境变量 ARK_API_KEY（Bearer）
```

请求体，每一项都是实测换来的：

```json
{
  "model": "doubao-seedream-5-0-lite-260128",
  "prompt": "<质感描述> + <固定约束段>",
  "size": "2160x2880",
  "n": 1,
  "watermark": false,
  "response_format": "url",
  "output_format": "png",
  "sequential_image_generation": "disabled"
}
```

| 参数 | 为什么是这个值 |
|---|---|
| `size: 2160x2880` | HTML 画布 1080×1440，`shot.js` 用 `deviceScaleFactor:2` → 输出 2160×2880 物理像素。底图必须按**物理**像素出。实测：1680×2240 的底图被放大 1.286×，拉普拉斯方差从 64.3 掉到 24.3（只剩 38%），纸纹从「印刷」变成「打印机脏了」，而且只在全尺寸暴露、缩略图看不出来 |
| 比例必须精确 **0.75** | CSS 是 `background: url() center/cover`，`cover` 的语义是「铺满并裁掉多余」。比例一旦不等于 0.75，两侧被居中裁掉，**钉在右上角的网点会被直接裁出画面，且不报任何错**——底图只是看起来「变干净了」 |
| `output_format: "png"` | **少了这行就是 JPEG。** 服务端默认返回 JPEG，字节照样写进你给的 `.png`，退出码仍是 0。JPEG 压缩对网点这种高频内容出块状伪影，垫在文字层下面会脏。第 1、2 集就是这么踩的 |
| `watermark: false` | 不要水印 |
| 不降级 | 降级到 4.5 时某些封装会自动摘掉 `output_format` → 请求成功 → 默认 JPEG → 静默变质 |

## 固定约束段（每次都追加，别删）

```
只在画面右上角有一片半色调网点飞溅，网点颗粒清晰锐利。
画面左侧、中部、下部保持完全干净的空白纸面，没有任何网点、色斑或痕迹。
整张图不含任何文字、汉字、字母、数字、标点、logo、水印，
也不含任何昆虫、动物、人物、器物或可辨认的主体图形——只要纸张本身和印刷痕迹。
```

少了这三句，模型会自作主张加字、加虫、把网点撒得到处都是。

**网点为什么钉右上**：那块是构图上最不放正文的地方；固定位置之后，写 build 脚本时知道
「标题色块右端不能越过 x≈714」，否则会压在网点上（门禁拦不住这条）。

## 密钥怎么给

**不写进 kit，不写进代码，不进 git。** 运行时给环境变量：

```bash
export ARK_API_KEY=<你的 key>
python3 scripts/gen_bg.py -o 第N集-XX/素材/tex_<名字>.png "<质感描述>"
```

key 放在一个不进 git 的 `.env` 里，用之前 source 进来：

```bash
set -a && . <你的 .env 路径> && set +a     # .env 里一行：ARK_API_KEY=xxx
python3 scripts/gen_bg.py -o ... "..."
```

> Kai 本机：`~/AIFun/kaiswords/imagen/.env`。

没有 key 时脚本 fail-closed 并明确报错，**不会**静默降级或绕道。

## 落盘自验（三道闸，都在 `gen_bg.py` 里）

不要只信退出码。九集的教训是：**退出码 0 不等于文件对。**

| 闸 | 查什么 | 失败时 |
|---|---|---|
| 1 | 文件存在 | die |
| 2 | **PNG 魔数** `89 50 4E 47 0D 0A 1A 0A` | die，并提示多半是降级成了 JPEG |
| 3 | PIL 能真正解码 + 尺寸 + 比例 `\|w/h − 0.75\| ≤ 0.001` | die |

第四道闸在出图那步：`build_ep<N>.py` 开头的 `check_bg()` 会再验一次魔数、比例、宽度。
**闸设在出图这步才绕不过去**——脚本里的闸只挡得住走这个脚本的人。

```python
def check_bg(path: Path) -> None:
    head = path.read_bytes()[:8]
    if head != b'\x89PNG\r\n\x1a\n':
        raise SystemExit(f'✗ 底图不是真 PNG：{path}\n  魔数 = {head.hex()}')
    from PIL import Image
    w, h = Image.open(path).size
    if abs(w / h - 0.75) > 1e-6:
        raise SystemExit(f'✗ 底图比例 {w}×{h} = {w/h:.4f} ≠ 0.75：{path}')
    if w < 2160:
        raise SystemExit(f'✗ 底图 {w}×{h} 小于 2160×2880：{path}')
```

**魔数速查**：真 PNG 开头 `89504e470d0a1a0a`；JPEG 是 `ffd8ff...`。

```bash
xxd -p -l 8 素材/tex_xxx.png     # 一眼看出来
```

## 生成后必做两件事

### 1. 测实测均色（脚本查不了，但有工具）

```bash
python3 scripts/measure_bg.py 第N集-XX/素材/tex_xxx.png
```

输出实测均色和 CIE L*。**build 脚本里的 `PAPER` 用实测值，不是 prompt 里的标称色。**
九集实测偏差 1~4 个 L* 单位，差这一点点，SVG 里用 PAPER 填充的部分（翅膀、纸色描边）
就会和底图对不上，纹理线浮出来。

`L* ≤ 92` 直接重生，DNA 规则 1 是硬线。算法必须是 **CIE L\***，不是 HSL 的 L、不是 HSV 的 V
（三种算法能差 5~25 点，扩色板时必然选错纸）。

### 2. 人眼看两件事

- 图里确实**没有文字笔画**（即使 prompt 明令零文字，模型偶尔还是会画）
- 网点确实钉在右上，左中下是干净的

## 一集只生一次

**同一集的四张图必须共用同一张底图。** series 感来自纸纹走向和网点位置一致。
重出旧集的图要用回当集那张，重生的纸纹不一样就不是一套了。

换色板才生成新的。已验证可用的色板在 `08-视觉规范.md` 的色板表里，九集用过：
裸粉 / 奶油 / 浅灰蓝 / 薄荷 / 浅杏 / 浅柠 / 浅藕粉 / 浅天青 / 晴空蓝。
