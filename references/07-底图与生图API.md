# 07 · 底图与生图 API（两个脚本：`gen_bg.py` 底图 / `gen_art.py` 生物主体）

- **底图**：每集固定生成**一张**，四张图共用（`gen_bg.py`，默认 Flash）。
- **生物主体**（人物、动物、昆虫、吉祥物要嘴 / 要亲 / 要和别的生物互动）：先过 `12-生图主体与和谐.md` 第一节的三个例外（姿态方向数量就是结论、物件 / 液体 / 场景 / 微生物、恶心题），过了才生，每个构图先出 3 张（`gen_art.py`），规则和边界在 12 号文档。
- 除此之外全部本地：文字是 HTML/CSS + Chrome 截图，图示和标注是代码，门禁是本地 Playwright。

---

## 为什么不让模型直接出成品图

试过，不行。实测失败模式：
- 中文多字、错字、糊字，一张图里能错三四处
- 文字被裁边
- 标注位置控不准
- 图示（结构、箭头、数量）画不准
- 同一个角色每次生成都不一样（用吉祥物参考图可以部分锁住，见 12 号文档第三节，6 次里 3 次清楚保持）

所以是**分层分工**：

| 层 | 谁做 | 为什么 |
|---|---|---|
| 底图（纸纹、网点、褪色渍） | Seedream 生成（`gen_bg.py`） | 质感是模型的强项，且不含任何需要精确的东西 |
| 生物主体（人物、动物、昆虫、吉祥物要嘴 / 要亲 / 要和别的生物互动） | Seedream 生成（`gen_art.py`）+ `art_grade.py` 调色 | 表情、姿态、质感；代价是准确性要审 |
| 文字、标注、数据、框 | HTML/CSS + Chrome 截图 | 中文永不出错，像素级可控 |
| 机制图示、解剖剖面、字形图解 | 代码（SVG / HTML） | 要精确、要标注 |
| 物件、液体 / 气雾、场景、微生物、无足幼虫、吉祥物站桩和代码眼型够用的表情 | 代码（SVG / HTML） | 形制、尺度、「没有」都是断言；场景画在框底（12 号文档第一节） |

**底图里绝对不能有文字、主体、生物。** 脚本的约束段写死了这条。

## 模型与引擎（2026-10-22 实测都能调通）

| 模型 | id | 用途 | 最大像素 | 官方价（R1 摘要，未逐字核对） |
|---|---|---|---|---|
| **Flash**（默认） | `doubao-seedream-5-0-flash-260915` | 底图、生物主体 | 约 462 万（1856×2480、2048×2048 可以，2160×2880 不行） | 0.12 元/张 |
| Pro | `doubao-seedream-5-0-pro-260628` | 道具、姿势反复画错时换用 | 同上 | 0.30 元/张（≤261 万像素），更大 0.60 元 |
| Lite | `doubao-seedream-5-0-lite-260128` | **官方 2026-10-21 标「即将下线」**，只有 `gen_bg.py --engine lite` 用 | 3K/4K（2160×2880 原生） | 0.22 元/张 |

端点 `https://ark.cn-beijing.volces.com/api/v3/images/generations`，密钥环境变量 `ARK_API_KEY`（Bearer）。方舟控制台要**逐个开通**模型。
Pro/Flash 不支持组图（请求里不要带 `sequential_image_generation`），官方没有 Pro/Flash 专用的提示词指南，`seed` 不可用（同一提示词不能复现）。

### `gen_bg.py` · Flash 引擎（默认）

```json
{
  "model": "doubao-seedream-5-0-flash-260915",
  "prompt": "<用户的质感描述> + <固定约束段>",
  "size": "1856x2480",
  "n": 1,
  "watermark": false,
  "response_format": "b64_json",
  "output_format": "png"
}
```

| 参数 | 为什么是这个值 |
|---|---|
| `size: 1856x2480` | 3:4，约 460 万像素，Flash 的上限。再用 Lanczos 放大 1.16× 到 **2160×2880**（HTML 画布 1080×1440，`shot.js` 用 `deviceScaleFactor:2`，底图要按物理像素）。放大会影响高频细节，最终需看原尺寸与缩略图，不把某批指标当质量保证。 |
| 比例必须精确 **0.75** | CSS 是 `background: url() center/cover`，比例不等于 0.75 时两侧被居中裁掉，**钉在右上角的网点会被直接裁出画面，且不报任何错** |
| `response_format: "b64_json"` | 图直接在响应体里，**不走 TOS 下载**：TOS 域名（`ark-acg-cn-beijing.tos-cn-beijing.volces.com`）从本机经常 TLS 握手被卡（三个 IP 都 25 到 60 秒无响应），图生成了、钱花了却拿不到。大响应偶尔 `IncompleteRead`，脚本重试 3 次（**重发可能重复计费**） |
| `output_format: "png"` | **少了这行就是 JPEG。** 服务端默认返回 JPEG，字节照样写进你给的 `.png`，退出码仍是 0。JPEG 压缩对网点出块状伪影。lite / pro / flash 都认；4.5 / 4.0 不认 |
| `watermark: false` | 不要水印 |

### `gen_bg.py --engine lite`（保留，即将下线）

同一请求体，但模型 `…-lite-260128`、`size: 2160x2880`（原生，不放大）、`sequential_image_generation: "disabled"`。lite 路径也已改成 `b64_json`。降级到 4.5 时某些封装会自动摘掉 `output_format` → 默认 JPEG → 静默变质，所以脚本不做降级。

## 固定约束段（脚本自动追加，不用自己写）

Flash 引擎（`CONSTRAINTS_FLASH`，以脚本为准）：纸面整体极浅、接近白色，只带一点色调；右上角一大团浓重的半色调网点飞溅（**颜色是比纸面深很多的同色系深色**），网点粗大、清晰锐利，中心最密、向外渐稀；其余区域保持完全干净的浅色纸面；没有任何文字、汉字、字母、数字、标点、logo、水印，也没有任何昆虫、动物、人物、器物或可辨认的主体图形。
lite 引擎用旧的约束段（网点「颗粒清晰锐利」，没写浓重粗大）。

**网点颜色口径：Flash 引擎下网点 = 纸色同色系深色，不跟第二强调色走；不要在用户提示词里再写网点颜色**，否则一条提示词里同时出现「网点为朱红」和「同色系深色」。

**网点为什么钉右上**：那块是构图上最不放正文的地方；固定位置之后，写 build 脚本时知道标题色块右端不能越过网点（门禁拦不住这条）。**Flash 的网点团比 lite 大、更靠左**：网点团左缘（CSS 像素）Flash 约 479 到 614，lite 定稿底图 666，所以 08 里的「x≥714」对 Flash 不成立；`gen_bg.py` 落盘后会打印网点团最左 x，**以它为准**。

## ★ 推荐：先挑纸色，再「质感 + 事后上色」（2026-10-22）

```bash
python3 $KIT/scripts/pick_paper.py                       # ① 列出还没用过、离已用纸色足够远的纸色（也告诉你还剩几个空位）
python3 $KIT/scripts/gen_bg.py --paper '#B8FEF4' -o 第N集-XX/素材/tex_<名>.png   # ② 模型只出质感，纸色和网点色由 tint_bg.py 落到目标 hex
python3 $KIT/scripts/measure_bg.py 第N集-XX/素材/tex_<名>.png                      # ③ 复测（对已用纸色的 ΔE、L*、网点最左 x）
```

- 为什么：Flash「要么色相丢光（L* 95，近白灰）、要么 L* 掉到 80」，靠提示词碰色相不行；纸色空位又只剩一小块，不能碰运气。
  所以**颜色不交给模型**：`--paper` 模式下提示词只要质感（默认 `纸浆纤维清晰，有几道细细的折痕。`，省略也行），
  约束段改成「极浅白纸、近乎无色、铺满画面无纸边、深色粗网点」，出图后 `tint_bg.py` 做双色映射（只看亮度，原图色相丢弃）。
- **提示词的坑（真实踩到）**：第一版约束写「近乎中性的米白或浅灰白」，模型把它画成**一张摆在白桌面上的纸**（四周有白边和阴影），上色后整图带框、不能用。
  现在的约束写成「纸面铺满整个画面，四边没有纸边、桌面、阴影或背景」，并沿用「极浅的白色纸面，几乎没有颜色」这个已验证过的句式。改约束要重新出图验证。
- 原图自动另存为 `<名>_src.png`；同一张原图可以用 `tint_bg.py` 换色重上（不再付费），但**每集的底图最好各出各的**，不然网点团位置、折痕会一模一样，系列里会被看出来。
- 限制：清晰度仍是 lite 的 71 到 78%（上色不改变它）；网点是「墨点泼溅 + 半色调」混合，不是 lite 那种规整的网点阵；`--paper` 只支持 flash 引擎。
- **新色优先，耗尽可复用**：候选容量取决于自己的已用色表。没有合格新色时复用明亮旧色，换强调色与构图并登记；保持 L*>92，不降低亮度求新。
  **继续「每集换纸色」是靠放宽规则还是允许复用旧纸色，要本人拍板**（见 12 号文档）。

## prompt 怎么写（Flash，不用 --paper 时）

```
极浅近白的<色相>纸面，比白色略深一点，几乎接近白色、只带一点点<色相>色调（整体明度很高），纸浆纤维清晰，有几道细细的折痕。
```

- 网点那段由约束段负责，不写。旧写法（「极浅<颜色名>纸面…半色调网点为<深色>」）在 Flash 上会出灰白、网点淡而小的纸，不要用。
- **hex 不可靠**：Seedream 会冲淡请求色，要写「比白色略深一点」这类相对说法，再用 `measure_bg.py` 实测。
- 色相问题：靠提示词出色相的 Flash 纸要么近白（色相丢）要么偏深（L* 80），**已用上面的 `--paper` 事后上色解决**；这里保留是为了说明不加 --paper 时为什么不推荐。

## 密钥怎么给

**不写进 kit，不写进代码，不进 git。** 运行时给环境变量：

```bash
export ARK_API_KEY='YOUR_API_KEY_HERE' # placeholder: replace with your own key
python3 $KIT/scripts/gen_bg.py -o 第N集-XX/素材/tex_<名字>.png "<质感描述>"
```

key 放在一个不进 git 的 `.env` 里，用之前 source 进来：

```bash
set -a && . "$HOME/path/to/your.env" && set +a     # replace with your own 0600 .env file
```

没有 key 时，按上一节设置 `ARK_API_KEY` 环境变量；脚本不会读取账号个人目录里的 `.env`，不会打印或保存 key。

没有 key 时脚本 fail-closed 并明确报错，**不会**静默降级或绕道。

## 落盘自验（`gen_bg.py` 里的闸）

不要只信退出码。**退出码 0 不等于文件对。**

| 闸 | 查什么 | 失败时 |
|---|---|---|
| 1 | 文件存在 | die |
| 2 | **PNG 魔数** `89 50 4E 47 0D 0A 1A 0A` | die |
| 3 | PIL 能真正解码 + 尺寸 + 比例 `\|w/h − 0.75\| ≤ 0.001` | die |
| 4 | Flash 回的尺寸必须等于请求的 1856×2480（不对就报错，**不放大**，免得拉伸变形） | die |
| 5 | 纸色 L*（左半 + 下半）> 92（DNA 规则 1） | die，提示写「极浅、接近白色」重生 |

出图那步还有一道：`build_ep<N>.py` 开头的 `check_bg()` 会再验一次魔数、比例、宽度。**闸设在出图这步才绕不过去**——脚本里的闸只挡得住走这个脚本的人。

```python
def check_bg(path: Path) -> None:
    head = path.read_bytes()[:8]
    if head != b'\x89PNG\r\n\x1a\n':
        raise SystemExit(f'✗ 底图不是真 PNG：{path}\n  魔数 = {head.hex()}')
    from PIL import Image
    w, h = Image.open(path).size
    if abs(w / h - 0.75) > 1e-6:
        raise SystemExit(f'✗ 底图比例 {w}×{h} = {w/h:.4f} ≠ 0.75：{path}')
    if w < 2160:
        raise SystemExit(f'✗ 底图 {w}×{h} 小于 2160×2880：{path}')
```

**魔数速查**：真 PNG 开头 `89504e470d0a1a0a`；JPEG 是 `ffd8ff...`。`xxd -p -l 8 素材/tex_xxx.png` 一眼看出来。

## 生成后必做两件事

### 1. 测实测均色 + 对已用纸色算 ΔE

```bash
python3 $KIT/scripts/measure_bg.py 第N集-XX/素材/tex_xxx.png
```

输出实测均色、CIE L* 和最近纸色色差。新色要求 ΔE≥8；复用须用 `--reuse-paper` 与 `--reuse-reason` 显式声明。build 的 PAPER 使用实测值。
**别用整图均值**（会把网点算进去，Flash 底图上整图均值能低 3 个 L* 以上）。
`L* ≤ 92` 直接重生，DNA 规则 1 是硬线。算法必须是 **CIE L\***，不是 HSL 的 L、不是 HSV 的 V。

### 2. 人眼看三件事

- 图里确实**没有文字笔画**（即使 prompt 明令零文字，模型偶尔还是会画）
- 网点确实钉在右上，左中下是干净的；记下 `gen_bg.py` 打印的网点团最左 x，标题色块别越过
- 纸的色相和已用的几集是不是太像

## 一集只生一次底图

**同一集的四张图必须共用同一张底图。** series 感来自纸纹走向和网点位置一致。
重出旧集的图要用回当集那张，重生的纸纹不一样就不是一套了。
换色板才生成新的。已验证可用的色板在 `08-视觉规范.md` 的色板表里。

## `gen_art.py`：生物主体

```bash
python3 $KIT/scripts/gen_art.py <名字>_a @第N集-XX/生图/prompt_<名字>.txt --out 第N集-XX/生图/raw --model flash --size 1536x1536 [--image 第N集-XX/ref/mascots_ref.png]
```

- 提示词只走 `@文件`，不要在 shell 里内联中文。写法见 `templates/art_prompt.md` 和 12 号文档第五节。
- `--model flash`（默认）/ `pro` / `lite`；Flash 约 20 到 30 秒/张（中位约 30 秒），Pro 约 50 到 75 秒；Pro 输出超过 261 万像素按 0.60 元，想省一半用 1536×1536 以内。
- `--image`：参考图（URL 或本地文件，可多次传；官方说 Pro/Flash 最多 10 张）。**吉祥物参考图实测 6 次里 3 次保持得清楚、2 次部分漂移、1 次失败；两张以上参考图未测**（12 号文档第三节）。
- 每次调用写 `<out>/<name>.json`（提示词、模型、尺寸、耗时、usage、重试次数、参考图），成败都留痕；同名文件不会被静默覆盖。
- **费用**：每张按官方价目；`IncompleteRead` 后整单重发可能重复计费，json 里有 attempts。
- 返回的不是 PNG（比如被服务端换成了 JPEG）、图截断，脚本会报错并写 json，不会静默写成 `.png`。
- 出图后：`art_grade.py` 去背景 + 吸附色板 → 合成（`build_ep_template.py` 的 `art_frame()`）→ 12 号文档第八节审查。

## 合规

每集发布前按目标平台当前界面主动声明 AI 参与创作，并遵守适用法规；具体入口和标识方式以发布时界面为准。相关资料在 `14-平台尺度与AI标识.md`。
公开材料没有找到“小红书普通笔记中亲吻插画”的明确允许 / 禁止条款；商业内容规范与自然笔记的适用范围也需区分（来源与局限见 14）。本流程的保守制作默认是：人物衣着完整、动作含蓄，不画舌吻、压倒或带性暗示的身体接触；使用原创虚构人物，不生成可识别真人肖像。这是制作风险控制，不是平台对每种画法的确定判定。
