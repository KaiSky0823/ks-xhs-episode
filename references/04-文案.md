# 04 · 文案与评论区

本节适用于小红书知识图文的标题、正文、hashtag 和评论回复。写作时优先用目标账号的公开发布样本校准语气；若项目方提供了经授权的风格资料，可按需参考。**不要在通用 skill 中硬编码私有路径、私人聊天或作者的个人经历。** 去 AI 味规则和脚本说明见 `10-去AI味规则集.md`。

## 发布文案流程（每集必过）

范围包括：卡片上每个字（气泡、标签、收尾、来源行）、标题和备选、正文、hashtag、评论区预备回复。

1. 写之前先读本集核查结论、情绪目标和目标账号的公开语气样本；没有样本就用短句、事实和白描，不模仿任何具体作者。
2. 写时先讲清内容，不编个人经历、身体感受或读者反馈；收尾写事实、一个具体动作，或者不写。
3. 跑自动检查：
   ```bash
   python3 "$KIT/scripts/ai_flavor_check.py" 第N集-XX/素材/[1-4]_*.html 第N集-XX/发布文案.md
   ```
   定稿卡命名必须是 `1_cover`、`2_answer`、`3_mechanism`、`4_egg`。FAIL 必须为 0；REVIEW 逐条处理或记录理由。
4. 用 `--dump` 收集将要发布的文字，再交给未参与写稿的审阅者做句式层以外的阅读。若平台支持多 agent 审阅，使用独立审阅者；否则由第二位读者复核。审阅者应只看提供的内容，不读取不相关的用户目录或浏览器资料。
5. 交付时记录脚本 FAIL / REVIEW 数量、人工审阅处理结果和四张卡的收尾句。

自动闸只识别句式，抓不住比喻太绕、逻辑链过长或语气失真；因此脚本通过不等于文案通过。**诚实的证据边界不能为了改句式删掉**，要换成读者听得懂的表达。

## 标题

主题词前置；直白问句或短陈述优先。标题不夸大证据强度，不用无事实依据的「震惊 / 唯一 / 真相」等加强词。备选标题要有明确差异，而不是只换一个形容词。

## 正文

正文可以留空，只保留 hashtag。需要补图外信息时给 1 到 2 句，必须是真实的补充，不能复述卡片。

可从四种方向选：

- **图外冷知识**：卡片没放的一条，必须标来源。
- **本集真实过程**：只写确实发生过的核查或制作过程；没有就不编。
- **更短复述**：用一句话讲清结论，不重复卡片原句。
- **只放 hashtag**：没有值得补充的内容时使用。

## Hashtag

```text
#原创 #<内容核心词> #<赛道标签> #<知识类标签>
```

按目标账号既有发布数据校准数量与搜索词；不要为了增加标签数量挂多个同义标签。

## 评论区预备答案

每集预备 6 到 8 条，覆盖：

1. **个体差异**：「我怎么没有 / 我不是这样」——解释个体差异，不否定评论者经历。
2. **相似现象**：「这不就是 XX 吗」——说明共同点和区别。
3. **健康边界**：「是不是病 / 严重吗」——不诊断；需要时给出就医建议。
4. **AI 标识**：「是不是 AI 画的」——如实说明生成和人工处理流程，不虚构作者贡献。
5. **画面准确性**：古装、物种、器物有争议时，准备说明哪些部分是示意、哪些细节已经核对；发现错就承认并更正。
6. **证据追问**：准备论文、机构或原始资料来源与证据等级。

写法：先直接回答，再补一条必要边界；默认简短；不求互动，不用评论回复替代事实核查。

## 数字与出处

每集维护「图上写的 / 出处 / 强度」表，回复追问时按表核对。**出处表是证据索引，不是发布文案**；未证实内容标明状态，不把搜索摘要写成原文已证实。
