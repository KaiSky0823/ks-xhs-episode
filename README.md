# ks-xhs-episode · 小红书冷知识图文，一集从选题到发布

> *An end-to-end workflow for short illustrated explainers: research → visual plan → code or image generation by subject → four cards → copy → QA → publish log.*

把选题、事实核查、画面设计、文案、门禁和发布登记放进一条可复用流程。适用于生活现象、身体与感知、动物、昆虫、历史文化、机制、辟谣等题材；每种题材先判断信息由代码还是生图承担，不默认“能生成就全部生成”。

## 为什么不让模型直接生成整张卡

文字、数字、标注和因果关系需要可控；生图更擅长带表情和姿态的主体。按职责拆开：

| 内容 | 默认方式 | 原因 |
|---|---|---|
| 文字、数字、标注、数据图示、方向或数量本身是结论 | HTML/CSS、SVG 或代码 | 可复核、可定位、可保证刻度和因果正确 |
| 纸纹、网点等纯质感底图 | Seedream 5.0 Flash | 只承担质感，不承载事实信息；纸色优先试新色，无法区分时可登记后复用旧纸色 |
| 人物、动物等需要传达特定表情或姿态的主体 | Seedream 生图 + 后处理调色 | 生动性是强项；形态与画面暗示仍须核查 |
| 物件、液体、场景、微生物、方向 / 数量型动作 | 默认代码；需要混合时按层拆开 | 形制、尺度、运动相位等本身可能是事实断言 |
| 吉祥物 | 常规表情和动作先用代码；需要嘴、亲吻或跨生物互动时再生图 | 保留角色一致性，避免不必要的参考图漂移 |

底图默认 1 次 API 调用；有生图主体时按每个构图先出 3 张预算，具体软上限和成本见 `references/12`。超过预算前先停下来复盘，不把重生当作默认解法。

## 一集怎么跑

1. **选题**：检查研究来源、可讲性、尺度与画面风险。
2. **核查**：先查证，再整理图上可用的事实、限定和必须画对的特征。
3. **方案**：四张卡分别写主 / 副情绪、画面能否承担、代码 / 生图分工、尺度、版式和预算；辟谣题额外登记传言来源与核查强度。
4. **制作**：挑纸色、生底图；生物主体按需生图、抠图调色；代码绘制文字、图示、场景和数据。
5. **审查**：几何 QA、去 AI 味闸、生图形态 / 物件审稿。
6. **冷读**：测主题是否看懂、情绪是否对题、物种 / 物件能否辨认、是否引发不适；模拟分数只提示问题，不单凭读数否决成图。
7. **交付**：四张图、文案与评论区预备答案。
8. **登记**：记录实际发布内容与当集复盘。

完整顺序与停步条件见 `SKILL.md`。此工作流提供检查与记录，不替代原始资料核查，也不保证平台分发结果。

## 安装

```bash
git clone https://github.com/KaiSky0823/ks-xhs-episode.git "$HOME/skills/ks-xhs-episode"
cd "$HOME/skills/ks-xhs-episode"
npm install
pip install -r requirements.txt
export KIT="$HOME/skills/ks-xhs-episode"
export PROJ="$HOME/xhs-project"          # 改成你的工作目录
export ARK_API_KEY='YOUR_API_KEY_HERE' # placeholder: replace with your own key
```

把克隆目录安装到你的 agent CLI 所识别的 skill 路径即可。

运行时使用 Seedream 5.0 Flash；Pro 只在具体构图或道具反复画错时作为备选。中文字体需安装 Noto Sans CJK SC 与 Noto Serif SC。详见 `references/00-环境与快速开始.md`。

## 适配自己的账号

更换账号名称、视觉 DNA、角色、语气、色板表与 hashtag 配方，见 `references/09`。不要沿用本示例的账号资产作为自己的身份。脚本会核对图像尺寸、色板、资源加载、几何和文字；不能验证的事实与情绪效果仍需人工核查和冷读。
